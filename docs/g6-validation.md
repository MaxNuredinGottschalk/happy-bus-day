# G6 보호자 방문 현황 — 구현 및 검증 기록

작업일: 2026-11-15 / 작업 브랜치: `user/g6-visit-status`

## 이번 작업 범위

기존 공유 방문 상태를 읽어서 보호자에게 현재 상태, 마지막 기록 시각, 다음 안내, 방문 정보를 보여줍니다. 상태 변경은 기존 데모 직원 패널이 담당합니다. 공유 데이터 구조와 어르신 화면은 변경하지 않았습니다.

기존에는 보호자 화면이 없었습니다. 이번에는 `#/g6`에서 현황을 확인할 수 있고, 데모 직원 패널에서 G6으로 이동할 수 있습니다. G1–G5 예약 기능과 G7은 이번 작업에 포함하지 않았습니다.

## 표시 규칙

| 현재 상태 | 주요 안내 | 순서 정보 |
| --- | --- | --- |
| 예약 확인 | 현장 직원에게 접수 요청 | 숨김 |
| 현장 접수 | 직원 접수 확인, 이용 시작 전 | 어르신 접수번호 |
| 대기 | 직원의 호출을 기다림 | 접수번호·지금 진행 번호·앞선 인원을 각각 표시 |
| 호출 | 호출과 실제 이용 시작을 구분 | 어르신 접수번호 |
| 이용 중 | 직원이 시작 기록 | 숨김 |
| 마침 | 직원이 완료 기록, 결과 공유는 별도 | 숨김 |

- 단계 목록은 현재 단계만 강조합니다. 이전 단계의 실제 기록 이력은 없으므로 지나간 단계를 완료 이력으로 표시하지 않습니다.
- 예상 시간은 기존 어르신 화면과 같은 방식인 `앞선 인원 × 1인당 평균 시간`을 사용하며 올림합니다. 시연 계산임과 변동 가능성을 안내합니다.
- 계산 근거가 없거나 잘못된 인원·시간이면 숫자 대신 “아직 알 수 없습니다”와 현장 안내를 표시합니다. 번호 차이로 인원을 계산하지 않습니다.
- 마지막 시각은 기존 `lastCheckedAt`의 상태 기록 시각입니다. 순서 숫자 수정만으로 이 값이 바뀌지는 않습니다. 새로고침을 현재 현장 확인으로 표현하지 않습니다.
- 대기 인원 0명이어도 호출이나 이용 시작으로 자동 전환하지 않습니다.
- 건강 상담 결과·사진과 공유 선택 내용은 표시하지 않습니다. 이용 완료를 알림 발송 성공으로 표현하지 않습니다.

## 검증 결과

`npm run build` 성공. `npm run lint` 성공이며 기존 `src/elderly/ElderlyApp.tsx`의 `only-export-components` 경고 1건이 남습니다. G6에서 새로 발생한 경고는 없습니다. `git diff --check`도 통과했습니다.

실제 Chromium 브라우저에서 다음 항목을 확인했습니다.

- 여섯 상태별 제목, 현재 단계 한 개, 순서 정보 표시 범위, G6 주소 유지.
- 완료 화면에 알림 발송 성공을 뜻하는 표현이 없음.
- 접수번호 80·진행번호 10·앞선 인원 2명일 때 2명과 약 10분 표시.
- 계산 근거 제거 시 이전 예상 시간 숨김. 음수 인원은 확인 중으로 표시하고 예측 금지.
- 앞선 인원 0명에서도 대기 상태 유지.
- 새로고침 후 저장된 상태 유지.
- 다른 탭의 직원 패널에서 호출 시 G6에 반영되고, 기존 어르신 화면은 E7로 이동.
- 320·360·390px 화면에서 기본 글자와 루트 글자 크기 200% 조건의 가로 넘침 없음. 세로 스크롤로 방문 정보 확인 가능.
- 모바일 G6 옆 데모 패널의 가로 넘침을 발견하여 G6에 한정해 패널 숨김 처리 후 재검증.
- 모바일 대기 화면과 데스크톱 예상 시간 불명 화면을 캡처하여 검토.

최초 페이지 로드 시 기존 `favicon.ico` 요청의 404가 확인됐습니다. G6 실행 오류는 없었습니다.

## 재현 방법

Node.js 설치 후 저장소 루트에서:

```powershell
npm install
npm run dev
```

`http://localhost:5173/#/g6`을 열고 오른쪽 직원 패널로 상태를 바꿉니다. 휴대전화 폭에서는 패널을 숨깁니다. 다른 데스크톱 탭에서 상태를 바꾸면 같은 브라우저의 G6 탭도 갱신됩니다.

자동 브라우저 확인을 다시 하려면 개발 서버를 켠 상태에서:

```powershell
New-Item -ItemType Directory -Force output/playwright
npx --yes --package @playwright/cli playwright-cli -s=g6 open http://localhost:5173/#/g6
npx --yes --package @playwright/cli playwright-cli -s=g6 resize 1100 900
npx --yes --package @playwright/cli playwright-cli -s=g6 run-code --filename scripts/verify-g6.js
```

확인 코드는 시연용 저장 상태를 바꾸며, 마지막에는 대기·접수번호 23·진행번호 19·앞선 인원 3·평균 5분으로 둡니다. 캡처와 브라우저 임시 기록은 Git에 포함하지 않습니다.

## 검증의 한계와 막스에게 확인할 사항

이번 결과는 기능·화면 검증이며 실제 사용자 평가를 수행한 결과는 아닙니다. 글자 크기 검증은 루트 글자 크기를 두 배로 설정한 조건이며 모든 기기의 확대 동작이나 접근성 전체 충족을 보장하지 않습니다.

현재 상태는 브라우저의 localStorage에 저장됩니다. 서버·실제 직원 시스템·서로 다른 기기 간 연동과 인증은 없습니다. `done`까지 표시하는 것은 시연 범위이며, 실제 운영에서 보호자에게 진행 상태·완료 상태를 보여줄 수 있는 범위와 동의 규칙은 먼저 합의해야 합니다. 건강 결과 공유 선택을 진행 상태 공개 권한으로 사용하지 않았습니다.

대기시간의 실제 산정 근거, 오래된 정보로 판단할 기준, 정확한 호출 장소는 미확정입니다. 임의 만료 시간·전화번호·이동 장소를 만들지 않았습니다. 화면은 마지막 기록임을 안내하며, 통신 장애 감지나 실제 알림 발송은 구현하지 않았습니다.

사용자 확인에서는 “호출과 이용 시작의 차이를 설명할 수 있는가”, “접수번호와 앞선 인원을 구분하는가”, “마침을 결과 공유나 문자 발송 완료로 오해하는가”를 우선 살펴보면 됩니다.
